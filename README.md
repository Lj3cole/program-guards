# 程式守衛隊 · Code Guardians（v0.6）

以程式概念為角色的單人像素塔防。十五位守衛、十五種小怪、六隻頭目，三個不同背景關卡，每關20波。網站使用原生HTML/CSS/JavaScript與Canvas，不需要API金鑰、登入或後端。

## 網址與作業對應

- GitHub Repository：https://github.com/Lj3cole/program-guards
- GitHub Pages：https://lj3cole.github.io/program-guards/
- 使用者需將本次更新上傳GitHub，Pages才會是新版；私有試玩部署是另一個服務。
- 根目錄AGENTS.md是AI開發規則，定義專案目的、檔案結構、畫風、功能、資料格式及擴充流程；網站附同一份副本。
- docs/extension-example.md記錄依規則擴充第14波及本次三關的實際例子。
- [作業繳交說明](docs/submission.md)：專案簡介、連結、規則用途、擴充方式與AI協助。

## 開啟與發布

解壓縮後，在專案資料夾執行 `python -m http.server 8000 --directory dist`（Windows可用 `py`），再開啟 http://localhost:8000 。也可在VS Code使用Live Server開啟dist/index.html。不要直接雙擊HTML，本專案使用JavaScript模組。

將完整專案上傳GitHub，保留 `.github/workflows/pages.yml`；Settings → Pages的Source選GitHub Actions，工作流程發布dist。無新增建置套件，無需npm install。

## 操作

- 上排顯示金幣、賞金、目前關卡與波次；中央戰場保留環形道路和4×4部署格。
- 召喚、選取資訊與合成、寶石升級、抽抽樂、倍速及暫停集中固定下排，不用垂直捲動。窄螢幕可左右滑動操作列；橫向使用較方便。
- 召喚自動補同款到三隻，再放空格。可連續召喚；拖曳整組移動，不同角色可交換。角色總數30，同格最多三隻同款。
- 選到同格三隻按合成，免費隨機得到下一階五種之一，各20%。第三階不再合成。
- 召喚階級機率75%／20%／5%；同階五種等機率，單一角色各15%／4%／1%。先檢查所有可能結果皆能放下，否則不抽、不扣款、不漲價。
- 開局200金幣，召喚20起每次成功加2；抽抽樂100起每次成功加50。小怪擊殺+3，頭目依關卡+100／150／200。
- 符號兵尾刀小怪30%機率額外+10，BOSS不觸發；寶石每隻小怪8%掉1顆，自動入帳。
- 戰力Lv.1起，每級增加原始傷害15%，最多Lv.10（+135%）；升級費1、2、4…256顆。正常三關不保證能升滿。
- 500金幣解鎖2倍速，本局可免費切換1×／2×。倒數、攻擊、出怪、效果都以遊戲時間加速。
- 第一、二關通關後可選繼續或結束；等待時時間停止。跨關保留所有角色、站位、金幣、寶石、戰力、倍速、費用、累計結果及限時效果剩餘時間；只重設本關波次。第三關通關才顯示全部完成。
- 重新開始清空整場戰役；無關閉網頁後存檔功能。
- 暫停或離開分頁會停止模擬；角色圖鑑與玩法說明可從上排開啟。

## 三關配置（試玩初值）

| 關卡 | 背景 | 普通波數量 | 第10／20波BOSS | BOSS血量 |
| --- | --- | --- | --- | --- |
| 1 | 地下石磚基地、暖色火燈 | 32～40 | 堆疊巨獸／死鎖雙生怪 | 11000／34000 |
| 2 | 藍綠資料工廠、電流終端 | 40～48 | 封包吞噬者／防火牆巨像 | 50000／65000 |
| 3 | 紅紫核心熔爐、熔岩裂縫 | 48～56 | 競態獵手／核心崩潰者 | 85000／110000 |

每關第10、20波只新增指定頭目，舊小怪保留。頭目限時60遊戲秒，2×下約30實際秒；存活敵人達80隻失敗。普通波最遲每30秒接下一波，場上與排程全部清空可提前接波。第一／二／三關基本敵人總數646／790／934，不含抽抽樂入侵。

小怪HP＝原始HP×1.10×本關起始倍率×本關成長率^(波次−1)，四捨五入。起始倍率1／8／18，成長率1.17／1.06／1.045。每關逐步加入新怪，也混用前關敵人。數值集中在stages.js，便於測試後調整。

## 抽抽樂

正負各五種，機率沿用原版。超頻／火力更新25秒；緩速／延遲／火力異常／Bug加速20秒；召喚干擾15秒。清理、援軍、入侵為一次性效果。同種限時效果只刷新，不疊加強度；暫停與關卡選擇凍結，跨關保留剩餘時間。免費援軍自動部署、不漲召喚費，無位置時排除援軍並按剩餘權重顯示有效機率。

## 專案結構與繼續開發

- dist/index.html、css/style.css：橫向介面與固定操作列。
- dist/js/main.js、game.js、render.js、scene.js：事件、戰鬥、素材與三關場景。
- dist/js/data/：config、guards、enemies、waves、stages、luck，集中管理資料。
- tests/：功能測試與模擬；docs/：擴充與平衡紀錄。

AI新增角色需先讀AGENTS.md，依guards.js資料格式新增唯一ID、程式概念與技能，加入指定階級池並同步機率說明與測試。新增怪物需設定stage、firstWave及sprite，波次自動混編；新關卡需另確認總關數與通關流程，不能只加一張背景圖。

## 驗證與界線

`npm test`：46項功能測試通過，涵蓋十五種召喚、新技能、三關資料、跨關保留、手動繼續／結束、最後通關、抽抽樂期限、原有操作與勝負。

`SIM_SEEDS=10 node tests/simulate.mjs`：十組固定策略（會合成、升戰力、頭目戰移動，不抽抽樂）均到第三關最終BOSS，七組完成全部三關，三組頭目超時。只連續召喚與升戰力、不合成或追蹤站位的三組對照，在第一關第20／10／20波失敗。這是模擬策略差異，不是玩家勝率，仍需實際試玩。

瀏覽器確認橫向版面、連續召喚、新角色圖鑑與寶石升級；手機尚需實機確認。更多紀錄見docs/balance-v06.md；舊版歷程見docs/version-history.md；舊開發規則見docs/agents-history.md。

## 來源與AI協助

玩法靈感來自《運氣拚輸贏》，像素冒險氛圍參考《靠裝勇者》，使用自己的名稱、美術、程式與數值，不使用原作角色、程式或圖片。生成式AI協助需求討論、AGENTS.md、角色圖集與程式實作。角色動態為位移及程式特效，非完整逐幀走路動畫。繳交請附自己的需求Prompt、生成結果、理解說明及操作截圖。
