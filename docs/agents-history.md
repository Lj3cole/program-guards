# 程式守衛隊：AI 開發規則

## 1. 專案目的與目前狀態

建立可在 GitHub Pages 遊玩的單人像素塔防網頁。玩家花遊戲金幣隨機召喚程式小兵、自由擺位、三合一升階，抵擋環形路線上的 Bug 怪物。

目前為 v0.6 三關戰役；第15節是最新規格，舊版數值與紀錄供追溯。最小可玩版本已實作，數值仍為試玩初值，尚未進行廣泛玩家平衡測試。玩法靈感來自《運氣拚輸贏》，使用自己的名稱、角色、美術與數值，不複製原作程式或素材。

後續 AI 開工前先閱讀本文件及現有程式。保留已確認玩法與能力；攻擊、血量等尚未設定的數值可提出試玩初值並明確標註，不能冒稱已通過平衡測試。實作或測試後同步更新文件狀態。

## 2. 技術與檔案結構

使用 HTML、CSS、原生 JavaScript 與 Canvas；不需要 API 金鑰、後端、登入或付費服務。網站須能以靜態檔案部署到 GitHub Pages。

網站檔案位於 `dist/`，以下路徑以 `dist/` 為相對根目錄。Repository 根目錄另有 AGENTS.md、README.md、tests/、docs/extension-example.md 及 GitHub Pages 工作流程；網站內附規則與說明文件副本，修改時須同步：

- `index.html`：遊戲首頁、操作說明及遊戲畫面入口。
- `AGENTS.md`：本專案開發與擴充規則。
- `README.md`：專案介紹、啟動方式、操作、來源與公開網站連結。
- `css/style.css`：網站與介面樣式。
- `js/main.js`：初始化、輸入事件與介面更新。
- `js/game.js`：遊戲狀態、更新迴圈、移動、戰鬥與結算。
- `js/render.js`：Canvas 場景、角色、敵人與特效繪製。
- `js/data/config.js`：經濟、時間、格子及怪物上限設定。
- `js/data/guards.js`：守衛資料。
- `js/data/enemies.js`：怪物與頭目資料。
- `js/data/waves.js`：依關卡產生20波配置。
- `js/data/stages.js`：三關名稱、背景、出怪增量、血量倍率與指定頭目。
- `js/data/luck.js`：十種抽抽樂效果的名稱、類別、權重、持續時間與說明。
- `js/scene.js`：原創像素地下基地靜態場景與燈火；以低解析 Canvas 繪製，不能消耗遊戲亂數。
- `assets/units.png`：五欄四列的透明像素圖集，sprite 編號採 row-major、零起算；0–2 小兵、3–10 守衛、11–16 小怪、17–18 頭目、19 留白。
- `assets/guards/`、`assets/enemies/`、`assets/effects/`：預留獨立素材目錄，目前角色從共享圖集讀取，攻擊特效由 Canvas 繪製。

檔名使用小寫英文與連字號，角色及敵人使用固定且唯一的英文 ID。所有資源使用相對路徑，不以 `/assets/...` 等網域根路徑引用，避免專案型 GitHub Pages 路徑錯誤。資料以 JavaScript 模組匯出，開發時透過本機 HTTP 伺服器預覽。

## 3. 視覺與頁面規則

- 整體採深色像素程式基地：深藍灰背景、方形立體按鈕、硬邊面板、格狀道路及亮色像素攻擊火花。保留環形道路與中央 4×4 格；中文說明以清楚易讀為優先。新增頁面與面板沿用 css/style.css 的色彩變數與既有類別，不混入淺色圓角介面。
- 全站使用繁體中文；程式角色保留原有英文詞彙，旁邊可加中文說明。
- 使用已確認的像素守衛與 Bug 怪物造型；圖片縮放保持像素邊緣，避免模糊。
- 角色、怪物、頭目需有清楚輪廓；血條、選取框和文字不能只靠顏色區分。
- 畫面包含：遊戲名稱、金幣、目前波次、下一波倒數、場上怪物數／上限、戰場、召喚與合成操作、選中角色資訊、開始／暫停／繼續／重新開始。
- 頭目登場時顯示頭目血條與獨立倒數；勝負後顯示清楚的結果。
- 手機與電腦都能查看及點選，主要操作不能依賴滑鼠懸停；縮放畫面後點擊座標仍須正確。
- 概念圖只用於造型參考，不將整張圖鑑當成已完成的遊戲精靈或動畫。正式素材以獨立透明 PNG 或有明確幀規格的圖集保存。

## 4. 已確認的核心玩法

### 戰場與操作

- 怪物沿外圍封閉環形路線持續移動，不因繞一圈就消失。
- 中央為 4 × 4，共 16 格；每格最多 3 隻相同 ID、相同階級的角色。
- 場上守衛總數上限 30 隻，各階級均算一隻。同格三隻算三隻，三合一後總數減 2。介面顯示目前數量／30，滿額不得召喚或扣金幣。
- 角色自動攻擊射程內敵人，玩家負責召喚、移動與合成。
- 召喚成功立即自動部署：優先補相同 ID 未滿三隻的格子，再使用第一個空格；同款滿三隻後另開空格。可連續召喚，玩家仍可拖曳調位。免費援軍也採相同流程。
- 召喚前檢查金幣、角色上限及放置空間。沒有可放位置時不扣金幣，不得暗中重抽改變機率。實作需保證每個可能的抽選結果都有合法去處，例如有空格，或召喚池全部十五種守衛各自均有未滿的同種格；不滿足時提示先整理位置。抽選與自動部署在同一次操作完成，不設待放置階段。
- 玩家拖曳同格整組角色移動，不拆分單隻；拖到空格則移動整組，拖到不同角色格則兩組交換位置。拖到相同 ID 的格子，總數不超過 3 才堆疊；超過則保持原位並提示。非法拖放不遺失角色，不增加角色總數。
- 同格恰好 3 隻相同角色才可按合成。合成結果留在原格；合成免費。
- 暫停時，移動、攻擊、出怪、倒數和效果計時全部停止，且不能召喚、移動或合成。
- 重新開始須清空金幣、角色、怪物、寶石、戰力、倍速、選取、倒數、效果與結果，再恢復開局狀態；不能重複建立遊戲迴圈。

### 三階角色

- 第一階：`bit`（Bit 位元兵）、`symbol`（符號兵）、`bracket`（括號兵）、`byte`、`bool`。
- 第二階：`print`、`for`、`if`、`array`、`cache`。
- 第三階：`function`、`return`、`break`、`debug`、`compile`。
- 召喚可產生三個階級：一階總機率 75%（五種各 15%）、二階 20%（五種各 4%）、三階 5%（五種各 1%）。階級內等機率，且不因場上角色改變機率。
- 三隻相同第一階角色合成隨機第二階，五種各 1/5 機率。
- 三隻相同第二階角色合成隨機第三階，五種各 1/5 機率。
- 第三階不能再合成；同格多隻角色各自保有戰力，不能只計算其中一隻。
- 所有已確認造型保留。新角色外形與技能見第15節。原有能力如下，傷害、攻速、射程與效果間隔採集中設定的試玩初值：

| 階級 | ID | 能力 |
| --- | --- | --- |
| 一階 | bit | 穩定單發攻擊 |
| 一階 | symbol | 攻速快、單發傷害低；親自擊殺小怪時 30% 機率額外獲得 10 金幣 |
| 一階 | bracket | 攻速慢、單發傷害高 |
| 二階 | print | 穩定單體輸出 |
| 二階 | for | 每次連射三發 |
| 二階 | if | 優先攻擊射程內血量比例低的敵人，目標低於 30% 血量時增傷 |
| 二階 | array | 每次同時攻擊最多三個不同目標，不將多目標傷害重複集中同一隻 |
| 三階 | function | 基本攻擊並定期施放範圍爆炸 |
| 三階 | return | 基本單體攻擊並定期擊退 |
| 三階 | break | STOP 中斷者：基本攻擊，定期對目標周圍 115 範圍釋放暈眩波；小怪 1.4 秒、頭目 0.35 秒 |
| 三階 | debug | 持續攻擊並定期對範圍內多隻怪物造成傷害 |

- 三階守衛都保有基本傷害，不能合成後只剩輔助效果。頭目暈眩時間及擊退距離減弱，倍率寫入設定，避免無限控制。
- 程式詞彙的解釋須正確；遊戲效果是比喻，不把 `return` 說成程式中的敵人擊退指令。

### 波次與勝負

- 總共三關，每關 20 波，怪物存量跨波保留，不在換波時清空。
- 一般波最遲每 30 秒開始下一波；若場上及一般／入侵排程全部清空則立即進波，持續戰鬥，波次之間不增加準備時間。第 1–4 波每波 32 隻、間隔 0.55 秒；5–8 波 34 隻、0.52 秒；9–12 波 36 隻、0.50 秒；13–16 波 38 隻、0.48 秒；17–19 波 40 隻、0.46 秒。頭目波仍只新增頭目。數量與間隔由 waveCount()、waveInterval() 統一決定。
- 場上存活怪物（含頭目）達到 80 隻時立即失敗。
- 第 10 波出現 `stack-overflow` 頭目，第 20 波出現 `deadlock` 頭目，各有 60 秒擊殺期限。
- 頭目期間停止下一波倒數，原有小怪繼續活動；擊敗頭目後才繼續波次。
- 頭目超時仍存活則失敗。第 20 波頭目死亡且所有已排程出怪完成、剩餘敵人清空，前兩關顯示繼續／結束選項，第三關才判定全部勝利。
- 第 10、20 波只新增一隻指定頭目，不生成當波小怪，但前面存活的小怪保留。
- 同一更新步驟同時出現擊殺與到期時，必須明確固定處理順序並驗證，避免勝負結果不一致。

## 5. 第一版試玩用經濟數值

以下是可調整的初始值，不是已完成的平衡成果：

| 項目 | 數值 |
| --- | --- |
| 開局金幣 | 200 |
| 召喚費用 | 首次 20，每次成功召喚後加 2 |

## 7. 資料欄位與擴充方式

首次實作時以以下欄位為資料契約，若需調整，連同使用端及本文件一起更新：

- 守衛：`id`、`name`、`tier`、`description`、`conceptMeaning`、`sprite`、`damage`、`range`、`attackInterval`、`attackType`、`effect`、`bounty`（無賞金能力為 null）。
- 敵人：`id`、`name`、`kind`（普通／進階／頭目）、`sprite`、`hp`、`speed`、`reward`、`ability`。
- 波次：`id`、`number`、`spawnGroups`（敵人 ID、數量與出怪間隔）、`bossId`、`bossTimeLimit`。
- 攻擊與效果的型別採既有程式明確支援的枚舉；沒有能力時用 `null`，不能填寫文字卻不實作效果。

### 新增角色

1. 先確認角色符合程式主題，分配唯一 ID、階級及素材。
2. 按既有欄位增加資料，補正確的程式概念解釋。
3. 若新增至召喚或合成池，明確重新分配機率，更新規則與介面說明；不可默默改變現有機率。
4. 既有攻擊類型優先；新類型只在需要時加入對應邏輯。
5. 驗證放置、移動、堆疊、攻擊、合成與素材路徑，更新 README 的內容清單。

### 新增怪物或關卡

1. 以固定資料格式新增怪物，確認波次引用的 ID 存在。
2. 新增關卡時明確設定出怪、頭目及勝利條件，不只新增外觀或描述。
3. 增加關卡或修改每關 20 波前，先確認新的總波數與頭目配置，再同步更新進度顯示及通關判定。
4. 至少試玩新增內容，記錄怪物累積、金幣與合成情況，不宣稱未測試的平衡結果。

## 8. 開發與驗證規則

- 先完成本文件，再依規則開發最小可玩版本；按資料、戰鬥、操作、素材逐步接上。
- 保留核心玩法，不自行增加多人連線、付費、登入、抽獎活動或無限模式。
- 所有距離與速度採一致座標及單位；用遊戲時間推進，不能讓高更新率裝置跑得更快。
- 更新本專案時，清楚說明修改檔案、原因、驗證結果與未完成項目。
- 必查：金幣不足、沒有位置、自動部署與連續召喚、三隻合成、第三階禁止合成、非法移動、暫停、頭目期限、80 隻失敗、第 20 波清場勝利、重新開始。
- 部署前確認沒有瀏覽器主控台錯誤、資源 404 或大小寫路徑錯誤；以 GitHub Pages 網址實際開啟與操作。
- README 記錄 AI 協助與玩法靈感；留下依 AGENTS.md 新增一個角色或波次的實際變更紀錄，展示可重複使用性。

## 9. 下一步與驗證界線

核心玩法、守衛能力、怪物定位及頭目波安排已確認，可依本文件開始製作。攻擊數值、怪物血量、出怪間隔與控制效果倍率尚無已驗證的定值，開發時集中設定一組試玩初值，並在 README 列出。

先完成最小可玩版本，檢查召喚、擺位、合成、20 波與勝負，再接上正式像素材質與動畫。不得用角色圖鑑或靜態畫面代替實際功能。公開前檢查角色是否符合參考造型，未完成的素材與動畫需明確列出。

完成後依同一資料格式新增一項角色或波次內容，記錄依 AGENTS.md 修改了哪些檔案、如何驗證，作為本作業延伸性的證據。新增項目若會改變三階數量或 20 波勝利規則，應先取得使用者的範圍確認。

## 11. v0.2 試玩改良

依玩家回饋適量增加出怪，以基值乘 1.10，再乘 1.17^(波次-1) 計算小怪血量；兩隻頭目血量為 11000／34000。初級角色 bit／symbol／bracket 傷害為 6／2.5／12，STOP 基本傷害 85，以範圍控制為主要特色。第五波加入耐打怪，平緩提高合成需求。小怪獎勵改為 3，避免數量增加造成金幣暴增。開局金幣、召喚費用、20 波、怪物 80 上限與角色 30 上限維持不變。

STOP 控制波以射程內攻擊目標為圓心，每 3.5 秒冷卻後於有攻擊機會時觸發。受控敵人實際停止移動並顯示 STOP 標記，黃色波紋顯示生效範圍；控制不額外造成技能傷害。暈眩不疊加延長，暈眩後一般怪有 0.6 秒恢復期、頭目 1.2 秒恢復期，期間不能再次暈眩，避免多隻 STOP 永久定怪。暫停時控制與恢復計時均停止。

測試需覆蓋範圍內／外目標、頭目抗性、停止移動、暈眩不重複刷新及恢復期；更新波次時不可繼續用舊版固定 20 隻的驗證條件。

v0.2 歷史測試（尚未加入遞增費用）：13 項核心測試通過，三組會合成的自動操作均完成 20 波（630、632、646 秒）。對照測試的三組純初級小隊在第五波存活怪物峰值為 15–17 隻、於第 10 波頭目超時；會合成小隊最終頭目約 39–47 秒擊敗。這些是固定策略模擬，尚需玩家實測；不得宣稱已全面平衡。

## 12. v0.3：運氣抽抽樂與遞增費用

本節取代舊版固定召喚費用規則。這些都是局內遊戲金幣，不包含儲值、真實金錢或付費機制。

- 召喚費為 `20 + 成功召喚次數 × 2`；抽抽樂為 `100 + 成功抽取次數 × 50`。兩者各自計數，同一局無上限遞增。只有成功時扣款一次、次數加一；餘額不足、滿額、無位置、暫停的操作不得扣款或漲價。免費援軍不增加召喚次數。
- 每次抽取一種結果，使用同一遊戲亂數來源；不可為了讓玩家贏而暗中重抽。介面顯示本次費用、上次結果、效果說明、目前有效機率，以及限時效果剩餘秒數。
- 十種效果基本權重總和為 100，正負各 50。見下表；不得無故變更機率或擅加新結果。

| ID | 類型 | 權重 | 實際效果 |
| --- | --- | --- | --- |
| overclock | 正面 | 12 | 全體攻速 +25%，攻擊間隔除以 1.25，12 秒 |
| power | 正面 | 12 | 全體傷害 ×1.25，12 秒，含連射與範圍技能 |
| slow | 正面 | 10 | 小怪移速 ×0.75、頭目 ×0.875，10 秒 |
| cleanup | 正面 | 10 | 現存小怪目前血量 ×0.8，不影響頭目，不直接發放擊殺獎勵 |

| lag | 負面 | 12 | 全體攻擊間隔 ×1.25，10 秒 |

- 召喚與援軍均自動部署。援軍只有在未達 30 隻，且四種二階每一種都有合法位置時才參與抽選；不符合時只移除 reinforce，其他權重按剩餘總和正規化，介面同步顯示。沒有放置空間不能先扣款再偷偷換獎品。
- 入侵怪使用獨立排程，跨波及頭目戰保留，不能被 beginWave 清掉；仍受 80 隻失敗條件限制。第 20 波勝利須連同額外排程一起清空。
- 暫停須凍結效果期限、額外出怪與所有操作；重新開始清空兩種費用次數、上次結果、全部限時效果及入侵排程。
- 場景升級為像素地下基地，含石磚、牆柱、火燈、管線、終端機與箱子，採自己的 Canvas 繪圖。裝飾不可遮擋怪物道路或部署格，座標與遊戲規則不變；禁止直接使用參考遊戲美術。
- 新增效果時先確認範圍，再更新 luck.js、game.js 實際行為、main.js 顯示、測試及本文件。只加文字而未實作效果不算完成。

## 13. v0.4：三階召喚與符號兵賞金
